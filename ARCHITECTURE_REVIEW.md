# Architecture Review
Generated: 2026-08-19T20:13:06.184Z
Score: 64/100

## Summary
The codebase has a clean, consistent core architecture — pure calculation modules (date.ts, engine.ts) are cleanly separated from I/O (storage.ts, rankApi.ts), and hooks consistently return discriminated-union result types ({ok:true}/{ok:false,reason}). However, there is heavy copy-paste duplication of small cross-cutting patterns (haptic-feedback wrappers, tab-bar item lists, empty/loading state components), one of those duplications has already produced a real navigation bug, and a large 'interface contract' file has silently drifted out of sync with every implementation it was supposed to describe.

## Issues
### Critical
- [dead_code] src/lib/contract.ts declares an entire 'do not modify' interface contract (CheckIn, Badge, User, useCheckInsFn, useBadgesFn, useRecoveryFn, useProfileFn, useBadgeToastFn, calculateStreakFn, fetchRankingsFn, etc.) that is not imported by any other file in the codebase, and every shape it declares now contradicts the real implementation (e.g. contract's CheckIn = {id, date, completed, memo} vs actual lib/types.ts CheckIn = {date, createdAt, source, memo}; contract's useCheckInsFn returns {checkIns, loading, addCheckIn(date, completed, memo), removeCheckIn} vs the real useCheckIns.ts returning {checkins, streak, isLoading, addCheckIn(date, source, memo), hasCheckIn, getCheckInsInRange, reload, today}). The file is stale, misleading, and unused. — Files: src/lib/contract.ts, src/hooks/useCheckIns.ts, src/hooks/useBadges.ts, src/hooks/useRecovery.ts, src/hooks/useProfile.ts, src/hooks/useBadgeToast.ts, src/lib/types.ts / Fix: Delete contract.ts, or if it must stay as design documentation for an automated multi-agent workflow, regenerate it from the current implementations (or generate it from the real types via `typeof`) and add a CI check that fails when it drifts from the actual exported signatures.
- [consistency] TAB_ITEMS is redefined independently in every page instead of being shared, and Rank.tsx's copy is missing three tabs: Home.tsx/Calendar.tsx/Stats.tsx/Badges.tsx all define the full 5-item list (홈/달력/통계/뱃지/랭킹), but Rank.tsx defines only [{홈},{랭킹}]. Because App.tsx routes /calendar, /stats, and /badges through the same RequireOnboarding shell as /rank, this isn't an intentional subset — it's a copy-paste bug that leaves users on the Rank screen unable to reach Calendar/Stats/Badges via the tab bar. — Files: src/pages/Rank.tsx, src/pages/Home.tsx, src/pages/Calendar.tsx, src/pages/Stats.tsx, src/pages/Badges.tsx / Fix: Extract a single `TAB_ITEMS` constant (e.g. src/lib/nav.ts or a prop-less export near FloatingTabBar) and import it everywhere; fix Rank.tsx to use the full 5-tab list.

### Warnings

Pages use them inconsistently — Home.tsx and Stats.tsx import EmptyState from EmptyState.tsx but LoadingState from StateView.tsx (splitting one conceptual 'state view' across two files/imports), while Calendar.tsx, Rank.tsx, and Recover.tsx import EmptyState from StateView.tsx instead. — Files: src/components/EmptyState.tsx, src/components/StateView.tsx, src/pages/Home.tsx, src/pages/Stats.tsx, src/pages/Calendar.tsx, src/pages/Rank.tsx, src/pages/Recover.tsx / Fix: Pick one EmptyState implementation (keep the IconBoundary-protected one, since CDN icon failures are a documented risk), merge LoadingState into the same module, and delete the other.
